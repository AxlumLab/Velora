# XAML 编译与预览工具链

## 1. 已有路径

当前 `velora_add_xaml` 调用 `velorac`，将 XAML 编译为 `.vxbf` 和仅连接控制器的代码后台，再与资源装成 `.vpak`。默认嵌入完整资源包，`EXTERNAL` 可部署外置包。旧 C++ 构树生成器保留回归用途，不继续增加独立语义。

`.vxbf` 保存类型、属性、资源、模板和绑定指令；`.vpri` 是资源查找索引；`.vpak` 承载索引和数据。它们均为 Velora 格式。应用作者声明页面与资源即可，索引作为包内部细节，不要求手工维护。保留主题、语言、DPI 候选、合并字典及资源诊断，服务正常 UI 开发。

## 2. 统一声明元数据

目标：内建、源码扩展和二进制插件从同一声明生成普通反射、XAML schema、编辑器补全与运行期描述，避免分别维护多份属性表。每类声明包含完整名称/TypeId、基类、属性 ID/类型/默认值/无效化规则、事件、内容规则、模板约定与所属模块。工厂与 C++ 访问器单独绑定，不把进程地址写进文件。

当前 `XamlIRBuilder` 只接受内建 schema，`RuntimeTypeRegistry` 也尚未提供插件工厂。实施时先引入可组合元数据目录，再让编译器和加载目标查询同一声明；不要仅取消未知元素诊断。

整个 schema fingerprint 的严格相等目前适用于固定集合。开放插件后，新增无关类型不应使全部旧页面失效。新二进制版本应记录实际引用的模块、类型和属性契约，逐项校验签名与版本；保持格式版本、大小边界和完整性校验。旧二进制只按其旧规则读取，不能静默跳过 fingerprint。变更属性含义、访问器契约或指令编码时重新生成页面与连接代码。

## 3. 文本编辑与实时预览

首版编辑器只做文本编辑、补全、实时预览和错误定位，不做拖拽设计器。预览使用实际控件和正式编译/加载器，不引入另一套运行时 XML 解释器。

编辑后合并短时间连续修改，增量编译受影响页面/字典，校验成功后在预览进程重建页面。允许丢弃输入和导航状态。失败保持上一个有效页面，报告文件、行、列和原因；创建中的对象、订阅和资源要事务回滚。预览进程与编辑器分开，原生控件崩溃后可重启。

| 修改 | 首版处理 |
| --- | --- |
| 普通值、资源、模板、动态 Binding | 编译二进制后重建页面；连接契约未变时复用已有代码后台 |
| x:Name/事件连接等生成契约变化 | 需要重新生成并原生编译连接代码，界面明确提示 |
| C++、反射声明、生成的 x:Bind 访问器 | 原生重编并重启预览；不解释执行 C++ |
| 插件二进制或 SDK 配置 | 重编匹配插件并重启预览进程 |

插件声明可用于任意平台的补全；实际预览需要当前预览平台的插件二进制。Windows 预览不能加载 Android `.so`。Android 视觉和输入最终在真机或对应目标预览宿主验证。

## 4. 实施顺序与验收

先恢复正式管线的 Windows 构建与 Gallery 加载，保留负例诊断、资源回环和绑定测试。随后以一个源码自定义控件打通元数据目录、编译、工厂及 loader，再接同声明的动态插件，最后增加编辑器进程与文件监视。

必须覆盖：新增无关插件后旧页面仍可加载；缺失/冲突声明有源位置诊断；模板各实例名称域隔离；主题切换重新解析资源；失败重载无对象或订阅残留；修改 x:Bind 明确触发原生构建。预览能显示控件不能替代正式应用、打包与 Android 验收。
